1. 概要

Diary は、Dropbox 内の日記フォルダに 1日1記事の Markdown ファイル（YYYY-MM-DD.md）を作成・閲覧・編集する、ブログ形式の日記アプリです。スマホの Chrome での利用を主として設計されています。

  • Dropbox 公式 API（OAuth / PKCE）で自分のアカウントに接続し、ブラウザから直接ファイルを読み書きします。サーバーや中継サービスはありません。
  • 「今日の日記」ボタンで、今日の日付のファイルがなければ新規作成、あればそのまま開きます。
  • ファイル冒頭のフロントマター（created / tags / author）は自動で管理されます。編集画面には本文だけが表示され、タグはチップ入力で編集します。
  • Obsidian で書いた既存の日記ファイルもそのまま一覧・閲覧・編集できます（フロントマターの未知キーは壊さず保持します）。
  • PWA としてホーム画面に追加できます。

2. 初期設定 1: Dropbox App Console でアプリを作る

Dropbox API を使うため、最初に一度だけ「自分専用の Dropbox アプリ」を作成します（無料・自分のアカウントだけで使う場合は審査不要）。

  1. Dropbox App Console を開き、Create app を押す。
  2. 次のとおり選択して作成する。
    • Choose an API: Scoped access
    • Choose the type of access: Full Dropbox（既存の日記フォルダ /07_memo/Cursor Vault/01_コラム・執筆/日記 のような任意パスへアクセスするため。App folder では不可）
    • Name: 任意（例: kiyohito-diary。全 Dropbox ユーザー間で一意な名前が必要）
  3. 作成後、Permissions タブで次の 3 つにチェックを入れて Submit。
    • files.metadata.read
    • files.content.read
    • files.content.write
  4. Settings タブの OAuth 2 → Redirect URIs に、Diary を開く URL をそのまま登録する（複数登録可）。
    • 公開版（GitHub Pages 等）: 例 https://<ユーザー名>.github.io/<リポジトリ名>/output/diary/
    • ローカル開発用: http://localhost:8909/
    正確な値は Diary の設定画面に「Redirect URI にはこの URL を登録」として表示されます（コピー用ボタンあり）。表示された URI と完全一致（末尾の / や index.html の有無まで）で登録してください。
  5. Settings タブ上部の App key を控える（次の手順で使用）。App secret は使いません（PKCE 方式のため不要。どこにも入力しないでください）。

3. 初期設定 2: アプリで連携する

  1. Diary を開き、ヘッダー右上の ⚙️（設定） を押す。
  2. Dropbox App Key に控えた App key を貼り付ける。
  3. 「Dropbox と連携する」を押す → Dropbox の許可画面が開くので承認する → 自動でアプリに戻り「連携済み」と表示される。
  4. 日記フォルダを設定する。「フォルダを参照…」で Dropbox 内をたどって選ぶか、パスを直接入力（例: /07_memo/Cursor Vault/01_コラム・執筆/日記）。
  5. 必要なら author（署名）と既定のタグ（新規作成時に自動で付くタグ。初期値「日記」）を変更する。
  6. 保存を押す。フォルダ内の日記ファイルが読み込まれ、一覧に表示される。
連携は端末（ブラウザ）ごとに 1 回だけ必要です。以降はトークンが自動更新されるため、開くだけで使えます。

4. 使い方

今日の日記を書く

  • 一覧右下の 「＋ 今日の日記」を押すと、今日の日付のファイル（例: 2026-07-23.md）を新規作成して編集画面が開きます。フロントマターの created には自動で今日の日付が入ります。
  • 今日のファイルが既にある場合、ボタンは 「📖 今日の日記」になり、押すとその記事が開きます。

閲覧

  • 一覧は日付の新しい順。カードをタップすると記事全文を Markdown 表示します。フロントマターは本文には出さず、日付・タグ・author のバッジとして表示します。
  • 上部のタグチップで絞り込みできます。
  • ヘッダーの 🔄 で Dropbox から再読み込みします（Obsidian 側の変更を取り込むとき）。

編集

  • 閲覧画面の 「✏️ 編集」から。過去の記事も編集できます（created は元の日付を保持）。
  • タグはチップ式: 入力して Enter で追加、× で削除。
  • 保存ボタン（または Cmd/Ctrl+S）で Dropbox に書き込みます。
  • 編集中の内容は約 1 秒ごとに端末内へ下書き自動保存されます（詳細は 6 章）。

テーマ

  • ヘッダーの 🌙 / ☀️ でダーク / ライトを切り替えます（既定はダーク）。

5. データ仕様

ファイル形式

日記フォルダ直下の YYYY-MM-DD.md のみを日記として扱います（他のファイル・サブフォルダは無視）。保存されるファイルの形式:

---
created: 2026-07-23
tags:
  - 日記
author: kiyohito
---

（本文 Markdown）
  • created: 新規作成時にその日の日付を自動入力。既存記事の編集では元の値を保持。
  • tags: 編集画面のチップで管理。インライン形式（tags: [a, b]）の既存ファイルも読み込めます（保存時はリスト形式に統一）。
  • author: 新規作成時は設定値を使用。既存記事の値は保持。
  • 上記以外のキー（Obsidian が付けたものなど）は、そのままの行として保持して書き戻します。
  • フロントマターのないファイルも閲覧でき、保存時にフロントマターが付与されます。

端末内に保存されるデータ（localStorage）

キー内容
diary_dbx_app_keyDropbox App Key
diary_dbx_tokensアクセストークン / リフレッシュトークン / 有効期限
diary_folder_path日記フォルダのパス
diary_authorauthor 設定値（初期値 kiyohito）
diary_default_tags既定タグ（初期値 ["日記"]）
diary_themeテーマ（dark / light）
diary_cache記事キャッシュ（rev + 本文）。2 回目以降の起動を速くし、変更のあったファイルだけを再取得するために使用
diary_draft編集中の下書き（未保存の本文・タグ）
日記の本体データはすべて Dropbox 上の .md ファイルです。localStorage はキャッシュ・設定のみで、消えても Dropbox から再取得できます。

6. 競合と下書き

上書き事故の防止（rev チェック）

保存時は「編集を開いた時点のファイル版数（rev）」を指定して書き込みます。Dropbox 側（Obsidian や別端末）で先に変更されていた場合は保存がブロックされ、競合ダイアログが出ます。

  • Dropbox 側を確認: 最新の内容を読み込んで表示します。自分の編集内容は下書きとして保持され、もう一度編集を開いたときに「復元しますか?」と提案されます。
  • 自分の編集で上書き: 最新版数を取得し直して、自分の編集内容で上書き保存します。

下書きの自動保存

  • 編集中の本文とタグは約 1 秒ごとに端末内（localStorage）へ自動保存されます。保存に成功すると消去されます。
  • 保存前にアプリを閉じたりリロードしても、次回起動時に編集の再開が提案されます。
  • 下書きは 1 件のみ（最後に編集していた記事の分）です。

7. トラブル対応

症状原因と対処
連携ボタンを押すと Dropbox 側で redirect_uri mismatch 等のエラー App Console の Redirect URIs と、設定画面に表示される URI が完全一致していない。設定画面の「URI をコピー」で正確な値を登録し直す。
「Dropbox 連携の有効期限が切れました」のバナーが出る リフレッシュトークンが失効（Dropbox 側でアプリ許可を取り消した場合など）。設定から「Dropbox と連携する」をやり直す。
「日記フォルダが見つかりません」 フォルダパスの誤り、または Dropbox 側でフォルダを移動・改名した。設定の「フォルダを参照…」で選び直す。
連携ボタンを押しても何も起きない / 暗号 API のエラーが出る file:// で直接開いている。OAuth と PKCE には HTTPS または http://localhost が必要。公開 URL かローカルサーバー経由で開く。
保存に失敗する（ネットワークエラー） オフライン時は保存できません。編集内容は下書きに残っているので、回線復帰後にもう一度保存する。
Obsidian 側の変更が一覧に反映されない ヘッダーの 🔄 で再読み込みする（起動時にも自動で同期されます）。

8. セキュリティと注意事項

  • 認証は OAuth 2 + PKCE。App secret は使わず、パスワードをアプリに入力することもありません。
  • リフレッシュトークンはこの端末のブラウザ（localStorage）に保存されます。共有 PC・他人の端末では使わないでください。使わなくなった端末では設定の「連携解除」を実行するか、Dropbox の「接続済みアプリ」から許可を取り消してください。
  • App Key は秘密情報ではありませんが、自分用アプリのため他人に共有する意味はありません。
  • 通信先は Dropbox 公式 API（api.dropboxapi.com / content.dropboxapi.com）と、Markdown 表示用 CDN（jsDelivr）のみです。
  • 記事本文の表示は DOMPurify でサニタイズしています。
